# Безопасность

## Что защищено

- Нет стандартных учётных записей, пароли — scrypt-хеши. Файл пользователей не попадает в Git/образ.
- Случайные непрозрачные токены, на сервере только SHA-256 токена; срок сессии 8 часов.
- HttpOnly + SameSite=Strict; Secure и HSTS при HTTPS. Нет токенов в localStorage.
- CSRF для входа, выхода и всех изменений; проверка same-origin. При заданном PUBLIC_ORIGIN дополнительно ограничивается Host. CORS wildcard отсутствует.
- WebSocket требует авторизации, получает данные адресно; выход/истечение сессии отключают соединение.
- До 5 попыток входа на IP за 5 минут и общий предел 30 в минуту. Размер JSON до 4 КиБ.
- Роли проверяются сервером; READ_ONLY включён по умолчанию. CLI-параметры проходят whitelist.
- Docker без shell, ограничение времени и объёма ответа. Логи максимум 2000 строк / 2 МиБ.
- DOM создаётся через textContent, нет inline JS и unsafe-inline в CSP. CSV защищён от формул.
- Аудит входов и действий без паролей/токенов, ротация 4 × 2 МБ.
- Контейнер работает не от root, cap_drop ALL, no-new-privileges, read-only rootfs, лимиты памяти/PID/CPU.
- По умолчанию порт доступен из сети. Для доступа только с сервера есть install.sh --local; для HTTPS — PUBLIC_ORIGIN и COOKIE_SECURE=true.

## Границы защиты

Доступ к Docker daemon — привилегированный. Само приложение, его зависимости или
подмена кода в публичном репозитории при установке могут использовать сокет с правами
его владельца. Режим наблюдения не ограничивает полномочия скомпрометированного процесса.

Для более строгой изоляции нужен отдельный socket-proxy с allowlist API методов или
Docker authorization plugin. Linux /proc монтируется только по явному выбору через
override; он также содержит информацию о хосте. Не монтируй весь корень хоста в панель.

Логи доступны всем авторизованным пользователям, могут содержать чувствительные данные.
Не давай доступ недоверенным людям. Не пробрасывай docker.sock/2375 в Интернет.
Прямой HTTP поддерживается для локальной сети. Для недоверенной сети используй HTTPS через reverse proxy или SSH-туннель: HTTP не шифрует пароль и трафик.

За прокси без доверия к X-Forwarded-For rate limit считается по адресу прокси; это
может ограничивать всю команду. Для сервера под нагрузкой добавь лимиты на прокси,
мониторинг процесса и регулярные резервные копии. Сессии и rate limits теряются при
перезапуске; для нескольких workers нужна другая архитектура.

Автотесты и pip-audit уменьшают риск регрессий, но не заменяют независимый аудит.
Сообщая об уязвимости, не публикуй в issue действующие пароли, токены и приватные логи.
